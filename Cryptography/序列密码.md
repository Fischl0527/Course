### 第一部分：序列密码（流密码）核心基础知识
**1. 核心加密原理：**

+ **一劳永逸的异或：** 序列密码的加解密过程通常只有极其简单的一步：明文位（或字节）与密钥流位进行异或（XOR）。
    - 加密：$ C_i = M_i \oplus Z_i $
    - 解密：$ M_i = C_i \oplus Z_i $
+ **安全性来源：** 异或操作本身没有安全性可言，序列密码的**绝对核心在于“密钥流生成器 (Keystream Generator)”**。只要生成的密钥流 $ Z $ 看起来像绝对的随机数，且永不重复，密码就是安全的。

**2. 核心组件：LFSR（线性反馈移位寄存器）**

+ **地位：** LFSR 是绝大多数硬件序列密码的“心脏”。它能用极少的硬件门电路，产生极长周期的伪随机序列。
+ **致命弱点：** 纯 LFSR 是线性的，极易被 **Berlekamp-Massey 算法** 破解（只需截获少量明密文对）。
+ **拯救方法：** 现代密码学通过加入**非线性元素**来掩盖 LFSR 的线性规律，主要流派有：
    - **非线性组合生成器：** 多个 LFSR 并行，输出结果经过一个非线性布尔函数过滤。
    - **非线性滤波生成器：** 一个长 LFSR，抽取其中几个特定位，经过非线性函数输出。
    - **钟控生成器：** 用一个 LFSR 的输出来控制另一个 LFSR 的移位速度（走走停停，破坏线性规律）。

**3. 同步与自同步（复习总结）：**

+ **同步序列密码：** 密钥流只依赖于种子密钥和初始向量 (IV)。失步即全盘崩溃，无误差传播。
+ **自同步序列密码：** 密钥流依赖于前 $ N $ 个密文。能自动恢复同步，有有限的误差传播。

### 第三部分：各算法深度解析与设计逻辑
#### 1. ZUC (祖冲之算法) —— 移动互联时代的中国骄傲
+ **加密逻辑 (三层结构)：**
    1. **顶层 (LFSR)：** 一个包含 16 个单元（每个 31 位）的线性反馈移位寄存器，负责提供长周期和良好的统计特性。
    2. **中层 (BR, 比特重组)：** 将 LFSR 取出的位进行打乱和重新组合，破坏原有的线性关系，传递给底层。
    3. **底层 (F 函数)：** 一个包含 S盒（类似分组密码中的非线性替换）的**非线性有限状态机**。它将线性的水流彻底搅浑，输出最终的密钥流。
+ **特性：** 结合了分组密码中 S盒的非线性强度与序列密码的高速，专为 4G (LTE) 和 5G 网络设计，抵抗代数攻击的能力极强。

#### 2. RC4 —— 曾经统治互联网，最终死于极简
+ **加密逻辑 (无需 LFSR，纯软件逻辑)：**
    1. **KSA (密钥调度算法)：** 根据种子密钥，把一个长度为 256 的数组 $ S $ （包含 0-255）像洗牌一样彻底打乱。
    2. **PRGA (伪随机生成算法)：** 两个指针 `i` 和 `j` 在 $ S $ 盒里不断跳跃，交换元素，并输出当前指向的值作为密钥流。
+ **特性与死因：** 代码只需十几行，速度奇快。但它有一个致命缺陷：**早期输出的密钥流与种子密钥有极强的相关性（偏差）**。黑客通过收集大量加密的早期字节（比如早期 WiFi 的 WEP 协议），直接就能统计出密码。现在已被各大安全协议（如 TLS 1.2+）强制禁用。

#### 3. A5/1 —— 钟控密码的典型代表
+ **加密逻辑 (多数表决钟控)：**
    - 内部有三个长度不同的 LFSR（19、22、23位）。
    - **核心机制：** 每次移位前，检查三个寄存器特定的“钟控位”。采用**“少数服从多数”**原则（例如钟控位是 1, 1, 0，多数是 1）。只有钟控位等于多数值的寄存器才允许移位。
    - 最终输出是三个寄存器末位的异或。
+ **特性与死因：** 钟控有效地破坏了纯 LFSR 的线性。但由于总的内部状态太小（只有 $ 19+22+23 = 64 $ 位，实际使用时往往被刻意弱化），黑客可以预先计算一张巨大的“彩虹表（时间-内存权衡）”。目前用一台普通电脑加上几块硬盘，即可在几秒钟内实时解密 GSM 通话。

#### 4. HC-128 / HC-256 —— 软件加速的怪兽
+ **加密逻辑 (动态表更新)：**
    - 它是专门为现代 32 位/64 位 CPU 设计的。它不搞什么位操作，直接对 32 位的数据块进行操作。
    - 内部维护着两个巨大的**隐蔽表（Table P 和 Table Q）**，每个表包含 512 个 32位整数。
    - 每次生成密钥流时，算法不仅从表里取数据，还会**根据提取的数据反过来修改另一张表**。
+ **特性：** “用表来更新表”，这种极其复杂的动态反馈机制让分析变得几乎不可能。在软件实现中，因为全是对数组的寻址操作，速度极其恐怖。

#### 5. Rabbit —— 迅捷如兔的并行利器
+ **加密逻辑 (耦合状态与计数器)：**
    - 内部维护着 8 个 32位的“状态变量”和 8 个 32位的“计数器”。
    - 每次迭代，计数器按特定的多项式递增，然后状态变量之间进行极其复杂的互相交叉计算（耦合）。
    - 它的运算大量使用了循环左移、加法和异或。
+ **特性：** 完全不依赖 LFSR 或 S盒，通过算术运算的溢出和位移来实现非线性。它极度适合软件实现，且由于内部并行的结构，在多核 CPU 或向量指令集（如 SIMD）下能发挥出极致的速度。
